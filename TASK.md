## 0. Кратко

Написать с нуля лёгкую локальную kanban-доску для личного использования.
Без облака, без внешних сервисов, без Docker, без pip-зависимостей.
Работает офлайн, запускается одной командой, данные лежат в git-репе проекта.

## 3. Главный принцип данных

**JSON — источник правды, git — история. Базы данных нет.**

- SQLite, PostgreSQL, любые ORM — **запрещены**. Это осознанное решение, не упрощение.
- Один файл на проект: `.board/board.json`
- Писать **атомарно**: временный файл в том же каталоге + `os.replace()`
- Формат — отформатированный JSON с отступами и **сортировкой ключей**,
  чтобы diff в git был читаемым глазами
- Вложения: `.board/attachments/<task-id>/<имя-файла>`, путь показывать в карточке
- Приоритет: **не падать на битом JSON** — показать понятную ошибку и предложить
  восстановление из git: `git show HEAD:.board/board.json`

## 5. Функциональные требования

### 5.1 Проекты и саб-проекты
- Список проектов, каждый привязан к git-репе (`repo_path`)
- **Первым проектом в доске идёт сам `FossilBoard`** (см. п.6)
- Модули (саб-проекты): создать / переименовать / удалить / перекрасить
- Фильтр доски по модулю: «показать только Ядро»
- Карточка хранит `module_id`

### 5.2 Таски
- CRUD: создать, редактировать, удалить (с подтверждением)
- Описание в markdown с предпросмотром (минимальный рендер: заголовки, списки, код, ссылки,
  **никакого innerHTML из пользовательского ввода** — экранировать)
- Колонки: Бэклог → К сессии → В работе → Ревью → Готово
- Drag&drop мышью между колонками **+ кнопки перемещения** (для телефона)
- Фильтры: модуль, метка сессии, «только с саб-задачами», поиск по тексту
- Порядок карточек в колонке — **стабильный, по ID** (чтобы не плодить diff-шум в git)
- **WIP-лимит**: если задан и превышен — колонка подсвечивается предупреждением

### 5.3 Саб-задаки
- Из карточки кнопка «Добавить саб-задачу» → создаётся с `parent_id`
- Список саб-засок внутри родителя, с прогрессом «3 / 5 готово» (считать по `column_id == "done"`)
- Сворачивание/разворачивание саб-тасок, состояние — в `localStorage`

### 5.4 Вложения
- Загрузка файлов на карточку: кнопка **+ drag&drop в браузере**
- Файл копируется в `.board/attachments/<task-id>/`
- Список вложений с размером и **относительным путём** (его и копировать в буфер)
- Удаление вложения
- Изображения открываются прямо в карточке, остальное — скачивание

## 6. Git-интеграция (самое важное — не упрощать)

Коммит с хэштегом `#K2C-12` обязан быть виден внутри карточки `K2C-12`,
с возможностью посмотреть diff по коду.

### 6.1 Поиск коммитов
- `git -C <repo_path> log --all --grep="#<task-id>" --pretty=...`
- **Не хранить в `board.json`** — всегда читать живое из git, иначе неизбежен рассинхрон
  (коммит сделан мимо доски → доска должна всё равно его увидеть)
- Показывать: короткий hash, дата, автор, subject

### 6.2 Diff
- Кнопка «Diff» → `git show <hash>`, вывод ограничить (например 4000 строк)
  и **честно предупредить, что вывод обрезан**
- Минимальная подсветка +/- в тексте, без библиотек

### 6.3 Обратная связь
- На карточке: «коммитов привязано: N»
- Если их нет — подсказка с кнопкой «скопировать»: `git commit -m "K2C-12: описание"`
- Раздел «История» на карточке: `task.events` + привязанные коммиты **в едином потоке по дате**

- Компактная тёмная тема (см. п.9), без баннеров и модалок
- В шапке — путь к git-репе проекта и текущий проект

## 8. CLI (обязательно)

Доска должна работать и без браузера — из терминала и из агента:

```bash
board.py init --id K2C --name "Kingdom-like" --repo /home/dipsi/projects/k2c-proto
board.py list [--module core] [--column wip] [--session вечер]
board.py add "Название" [-m core] [-d "описание"] [--parent K2C-3] [--session вечер] [-e 1]
board.py show K2C-12          # карточка + раздел «привязанные коммиты»
board.py move K2C-12 wip
board.py edit K2C-12 [--title ...] [--desc ...] [--module ...] [--estimate ...]
board.py done K2C-12
board.py rm K2C-12
board.py attach K2C-12 путь/к/скрину.png
board.py module add "Ядро" --color '#88ccee'
board.py module list
board.py serve [--port 8770]
```

- Коды выхода: `0` успех, `1` ошибка. Без декораций, всё в stdout/stderr
- Один файл `board.py` допустим, если читаем; лучше пакет с модулями

## 9. Оформление: Yaru **Dark** (тёмная тема)

Стиль — **Yaru Dark**, тема Ubuntu. Только тёмный вариант, светлый не делать

### 9.1 Источник (проверен, ветка `master`)

| Что | Точный путь в репозитории |

Получить: `git clone --depth 1 https://github.com/ubuntu/yaru.git /tmp/yaru`

### 9.2 Имена переменных — брать оттуда, не выдумывать
`common/yaru-colors-defs.scss` объявляет переменные вида `-yaru-<имя>`. Основные:
`-yaru-bg-color`, `-yaru-light-bg-color`, `-yaru-dark-bg-color`,
`-yaru-accent-color`, `-yaru-accent-bg-color`, `-yaru-accent-active-color`,

**Тёмный вариант получается сам**: в исходнике всё выбирается через
`if($variant == 'dark', ...)` при `$yaru_is_dark_variant`. То есть у тёмной темы
те же имена переменных — достаточно взять значения из dark-ветки.

- Если берутся из репозитория — указать в `CREDITS.md` источник и лицензию

  ShareAlike на производные работы). Для одиночного инструмента проще свои.
- Иконок нужно немного: `+`, `✎` (правка), `🗑` (удалить), `⇄` (переместить),
  `⧉` (копировать), `📎` (вложение), `◧` (diff), `⟳` (обновить), `⚙` (настройки)

### 9.5 Правила оформления
- Скругления 8px, тонкие бордеры (`1px solid` с цветом `-yaru-border-color`)
- Без объёмных градиентов, «стекла», тяжёлых теней
- Шрифт системный (`system-ui`), моноширинный — для ID, путей и diff
- Акцент — только на активных элементах, не заливать им пол-экрана
- Доска должна читаться как продолжение рабочего стола Ubuntu, а не как
  «веб-панель из 2015 года»

## 13. Критерии приёмки (не сдавать, пока не все)

1. `board.py init` создаёт `.board/board.json` в репе проекта
2. `board.py add` создаёт карточку с корректным ID; `git status` показывает изменение
3. `board.py show K2C-12` печатает карточку и раздел «привязанные коммиты»
4. Коммит с `#K2C-12` в сообщении появляется в разделе «привязанные коммиты»
5. Кнопка «Diff» показывает патч этого коммита
6. Саб-задача создаётся из карточки, у родителя виден прогресс «1 / 2 готово»
7. Скрин грузится через drag&drop, лежит в `.board/attachments/K2C-12/`, открывается в карточке
8. Модуль создаётся, фильтр по нему работает
9. `board.py serve` поднимает доску, карточка перетаскивается мышью в другую колонку и сохраняется
10. **FossilBoard зарегистрирован в собственной доске как первый проект** (п.14)
11. `python3 -m unittest` — все тесты зелёные
12. README написан и соответствует реальности (проверено запуском команд из него)
13. `git log --oneline` содержит осмысленную историю коммитов по ходу работы
14. Стиль соответствует **Yaru Dark** (п.9), палитра взята из dark-ветки
    (`common/yaru-colors-defs.scss`), иконки — инлайн SVG, внешних загрузок в рантайме нет
15. Светлой темы и переключателя тем нет — только тёмная

## 14. Самотест на себе (обязательно)

Доска проверяется на собственной репе — **FossilBoard является первым проектом в самой себе**:

- `board.py init --id FB --name "FossilBoard" --repo /home/dipsi/projects/FossilBoard`
- Реальные задачи этого проекта завести как карточки с модулями:
  `ядро`, `ui`, `git`, `docs`, `tests`
- Коммиты кода вести **с хэштегами** вида `FB-3`, `FB-7` —
  чтобы в карточке визуально появилась живая привязка
- Проверить сценарий целиком на себе: `add` → `move` → коммит с `#FB-N` →
  `show` показывает коммит → Diff показывает патч → вложить скриншот UI в карточку

**Это и есть приёмочный прогон.** Доска считается работающей, только когда
на собственной репе видно свои же коммиты в своих же карточках.

## 15. Что НЕ делать

- pip-пакеты, npm, внешние CDN, Docker, облачные сервисы
- SQLite / любая БД (решение: JSON + git — обосновано в п.3)
- Пользовательские аккаунты, роли, права, регистрация
- Отчёты, графики, аналитика, Gantt, диаграммы
- Realtime-синхронизация между несколькими пользователями
- Мобильное приложение, PWA-манифест, сервис-воркер — только обычная веб-страница
- Всё, что выходит за рамки single-user solo-инструмента
