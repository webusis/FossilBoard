# FossilBoard

Локальная микро-доска (kanban) для одного человека и его проектов.
Без облака, без внешних сервисов, без Docker, **без единой зависимости** —
только стандартная библиотека Python 3.14 и голые HTML/CSS/JS.

Данные лежат в git-репе проекта: `.board/board.json` — источник правды,
git — история. Базы данных нет и не предполагается.

## Быстрый старт

```bash
cd ~/projects/FossilBoard
./board.py init --id FB --name "FossilBoard" --repo "$PWD"   # создать доску проекта
./board.py module add "ядро" --color '#E95420'              # модуль (саб-проект)
./board.py add "Первая задача" -m ядро -e 2                 # карточка
./board.py serve --port 8770                                # http://127.0.0.1:8770
```

Доска слушает `0.0.0.0`, поэтому с телефона в той же сети открывается по адресу
`http://<ip-компьютера>:8770`.

## Устройство

```
FossilBoard/
├── board.py                  точка входа CLI
├── fossilboard/
│   ├── storage.py            модель данных, атомарная запись, вложения, реестр
│   ├── gitlink.py            живой поиск коммитов и diff по хэштегу
│   ├── server.py             REST поверх http.server
│   ├── cli.py                команды терминала
│   └── web/                  index.html · app.js · style.css (без сборки)
├── tests/test_board.py       45 тестов на stdlib unittest
└── .board/                   данные этой репы (для других — у них в своих репах)
    ├── board.json            источник правды
    ├── projects.json         реестр проектов
    └── attachments/<task-id>/<файл>
```

Схема `board.json` — `schema_version`, `project`, `columns`, `modules`, `tasks`,
`counters` (счётчик выданных номеров: **ID удалённой карточки не переиспользуется**).
Статус карточки — это её `column_id`; отдельного хранилища статусов нет.

Запись атомарная: временный файл в том же каталоге + `os.replace()`, ключи
сортированы, отступами — чтобы `git diff` читался глазами. Битый JSON не роняет
инструмент: доска скажет, что делать, и предложит восстановление из git.

### Если доска сломалась

`.board/board.json` — обычный файл в git, поэтому восстановление тривиально:

```bash
git -C ~/projects/FossilBoard show HEAD:.board/board.json > ~/projects/FossilBoard/.board/board.json
git -C ~/projects/FossilBoard log --oneline -5 -- .board/   # посмотреть историю правок доски
```

Та же подсказка с готовой командой выводится и в терминал (код выхода `1`),
и в JSON ответа API, так что веб-доска тоже не покажет белую страницу вслепую.

## Git-привязка по хэштегу

Коммит с `#FB-12` (или `FB-12: текст`) появляется прямо в карточке `FB-12`,
а кнопка **Diff** показывает патч. Привязки не хранятся в `board.json` — они
всегда читаются живьём из репозитория, поэтому коммит, сделанный мимо доски,
доска тоже видит.

```bash
# сделать карточку, написать код, привязать коммит
./board.py add "Разбор сохранений" -m ядро
git add -A && git commit -m "FB-1: разбор сохранений"
./board.py show FB-1        # карточка + раздел «привязанные коммиты»
./board.py show FB-1 --diff # плюс патч первого привязанного коммита
```

## Команды CLI

```bash
./board.py init --id K2C --name "Kingdom-like" --repo ~/projects/k2c-proto
./board.py projects                                  # реестр проектов

./board.py add "Название" [-m ядро] [-d "описание"] [--parent FB-3] \
                    [--session вечер] [-e 1] [-c wip]
./board.py list [--module ядро] [--column wip] [--session вечер] \
                [--parents] [--open] [-s поиск] [-v]
./board.py show FB-12 [--diff]
./board.py move FB-12 wip            # можно названием: move FB-12 "В работе"
./board.py edit FB-12 [--title ...] [--desc ...] [--module ...] [-e 2] [--session ночь]
./board.py done FB-12
./board.py rm FB-12 [-y]

./board.py attach FB-12 ~/shot.png --name FB-12-after.png
./board.py detach FB-12 FB-12-after.png

./board.py module add "Ядро" --color '#88ccee'
./board.py module list
./board.py module rename "Ядро" "Движок"
./board.py module color "Ядро" '#77216F'
./board.py module rm "Движок"

./board.py serve [--host 0.0.0.0] [--port 8770]
./board.py json                       # сырой JSON доски
```

Проект выбирается так: `--repo <путь>` → переменная `FOSSILBOARD_REPO` →
`--project <ID>` (или `FOSSILBOARD_PROJECT`) → единственный проект в реестре.

Коды выхода: `0` — успех, `1` — ошибка. Никакого декоративного вывода.

## Что умеет веб-интерфейс

- пять колонок, drag&drop мышью **и** кнопки ←/→ (последнее — для телефона);
- фильтры: поиск по тексту, модуль, метка сессии, «только с саб-задачами»;
- WIP-лимит колонки подсвечивает колонку и её счётчик;
- карточка: описание в markdown с предпросмотром, оценка, модуль, сессия;
- саб-задачи внутри родителя с прогрессом `N / M`, сворачивание (в `localStorage`);
- вложения: перетаскивание файла в браузере, просмотр картинок прямо в карточке,
  копирование относительного пути, удаление;
- раздел «коммиты» и единая лента «история» из событий карточки и коммитов;
- тёмная тема **Yaru Dark** (палитра взята из исходников темы, см. `CREDITS.md`),
  инлайновые SVG-иконки, ссылка на карточку через `#FB-12` в адресе.

## Тесты

```bash
python3 -m unittest discover -s tests -v      # 45 тестов, ~15 с
```

Покрыты: CRUD, запрет переиспользования ID, перемещение и прогресс саб-задач,
атомарность записи, вложения, поиск коммитов по хэштегу и diff, восстановление
после битого JSON, выдача картинки по HTTP байт-в-байт.

## Ограничения (осознанно)

- **Один пользователь.** Ни аккаунтов, ни ролей, ни прав: инструмент для себя.
- **JSON, а не БД.** SQLite/ORM сознательно не используются: файл в git даёт
  историю, diff и откат без отдельной инфраструктуры. На сотнях карточек
  переписывание всего файла может стать узким местом — это цена, которую платим
  за читаемую историю.
- **Нет realtime.** Несколько вкладок обновляются кнопкой ⟳; на телефоне
  достаточно перезагрузить страницу.
- **Нет отчётов, графиков, Gantt, аналитики** — доска, не трекер задач.
- **Привязка коммитов только по хэштегу** в сообщении: никакого машинного
  разбора текста описаний.
- **Diff обрезается** на 4000 строк с честной пометкой; полный патч — `git show`.
- Нет мобильного приложения и PWA: обычная веб-страница.
